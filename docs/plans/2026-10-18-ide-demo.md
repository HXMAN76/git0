# Git0 Relay IDE demo: build spec (2026-10-18)

Goal: show merge conflicts being caught **before they happen**. Two AI coding agents (A = "Alice's laptop",
B = "Bob's laptop") each work in their **own clone** of the same repo. Every tool call they make goes through
Pre/PostToolUse hooks that talk to the git0 MCP server, which keeps one global code-context graph in FalkorDB.
When B is about to write code that collides with what A already changed (same function, or a function whose
signature A changed, or code A wrote that calls what B is changing), the hook **blocks the write** and the
human is asked what to do, with concrete options.

The browser shows a VS Code-like IDE: both workspaces side by side, two agent chat panels, a live hook/MCP log,
and the FalkorDB graph with the conflict path lit up.

## Hard constraints

- Follow `CLAUDE.md`: all Cypher in `cypher/<name>.cypher` with `// name:` header + why-comment, loaded via
  `git0.core.queries.Q`. One query per write. No `EXISTS {}`. Fail loudly. Comment the *why*.
- LLM: Gemini via **pydantic-ai** (`pydantic-ai-slim[google,mcp]`, already in pyproject, v2.57). Model
  `gemini-3.1-flash-lite` (cheapest live model on this key; `gemini-2.5-flash-lite` returns 404 for new users).
  Settings: `ide_model` (default `gemini-3.1-flash-lite`), `ide_fallback_model` (`gemini-3.5-flash-lite`).
  Key from `GEMINI_API_KEY` (already in `Settings.gemini_api_key`).
  pydantic-ai v2 notes: `from pydantic_ai import Agent, RunContext`; `from pydantic_ai.models.google import GoogleModel`;
  `from pydantic_ai.providers.google import GoogleProvider`; `run.result.usage` is a **property** (not callable).
- Each demo visitor = one **session**: own FalkorDB graph `ide_<sid>` + own workspace dirs. Cleaned up on
  "End session", on page close (sendBeacon), and by an idle sweeper. On process start, delete every orphan
  `ide_*` graph and the workspace root. The existing room sweeper only touches `team_*`, keep it that way.
- Python 3.12, ruff line length 110.

## Default project (`demo_project/`)

A tiny Python shop. Every function is short so diffs are readable on screen.

```
demo_project/
  README.md
  shop/__init__.py
  shop/pricing.py     apply_tax(amount) -> 8% flat ; apply_discount(amount, pct)
  shop/cart.py        subtotal(items) ; calculate_total(items, discount_pct=0) -> subtotal, apply_discount, apply_tax
  shop/inventory.py   STOCK dict ; reserve(items) ; release(items)
  shop/receipts.py    format_receipt(items, total)
  shop/checkout.py    checkout(items, user) -> reserve, calculate_total, format_receipt
  tests/test_cart.py  2 tiny tests
```
`items` = list of dicts `{"sku": str, "price": float, "qty": int}`. Imports use `from shop.pricing import apply_tax`.

Scenario presets (the UI shows them as buttons; `GET /api/ide/presets` returns them):

- **A: Regional tax** - "Add region-based tax. Change `apply_tax` in shop/pricing.py to `apply_tax(amount, region)`
  using a `TAX_RATES` dict (US 0.08, EU 0.20, IN 0.18), and make `calculate_total` in shop/cart.py take a
  `region="US"` argument and pass it through."
- **B: Free shipping** - "Add shipping: in shop/cart.py change `calculate_total` to add a $5 shipping fee when the
  subtotal is under $50, and show the shipping line in shop/receipts.py `format_receipt`."
  (Collides with A on `cart.py::calculate_total` = same-symbol conflict.)
- **B: Gift cards** - "Add gift cards: in shop/checkout.py let `checkout` accept `gift_card=0` and subtract it from
  the total after tax by calling `apply_tax` on the discounted amount."
  (Calls `apply_tax` whose signature A changed = dependency conflict.)

## Code-context graph (FalkorDB, one graph per session)

Symbol id format: `"<path>::<qualname>"`, e.g. `shop/cart.py::calculate_total`. Module-level code is not a symbol.

Nodes
- `(:File {path})`
- `(:Symbol {id, name, path, kind: 'function'|'class'|'method', signature, body_hash, line, end_line})`
  `signature` = normalized `def name(args)` text; `body_hash` = sha1 of `ast.dump` of the node (ignores comments).
- `(:Agent {id: 'A'|'B', label})`
- `(:Change {id, agent, ts, path, symbol, kind: 'added'|'modified'|'signature'|'removed', summary,
   old_signature, new_signature})` - one per symbol per recorded write.
- `(:Intent {id, agent, task, ts, active: bool})`

Edges
- `(File)-[:DEFINES]->(Symbol)`
- `(Symbol)-[:CALLS]->(Symbol)` - rebuilt for a file's symbols on every record.
- `(Agent)-[:MADE]->(Change)-[:TOUCHED]->(Symbol)`
- `(Agent)-[:INTENDS]->(Intent)-[:TARGETS]->(Symbol)`
- `(Agent)-[:ACKED]->(Change)` - the agent has seen/absorbed this change (synced, or user said override).

Graph = "the shared truth of what the team's code looks like + who is changing what". Each agent's workspace
is its own clone; the graph is updated from every recorded write (= the agent "pushed context").

### Parser contract (`git0/code/parse.py`)

```python
class SymbolInfo:

    line: int; end_line: int
    calls: tuple[str, ...]   # resolved symbol ids this symbol calls (only project symbols)

def parse_file(path: str, source: str, known: dict[str, str] | None = None) -> list[SymbolInfo]
    # path uses forward slashes, relative to repo root. Syntax error -> raise SyntaxError (caller decides).
    # Call resolution: `from shop.pricing import apply_tax` + call `apply_tax(...)` -> "shop/pricing.py::apply_tax";
    # same-file call `subtotal(...)` -> "<path>::subtotal"; `module.func(...)` with `import shop.pricing as p` too.
    # `known` (name-or-dotted -> id) is optional extra resolution; unknown calls are dropped.

def parse_project(files: dict[str, str]) -> dict[str, list[SymbolInfo]]   # only *.py

@dataclass(frozen=True)
class EditDiff:
    added: list[SymbolInfo]; removed: list[SymbolInfo]
    modified: list[tuple[SymbolInfo, SymbolInfo]]          # (old, new), body_hash differs
    signature_changed: list[tuple[SymbolInfo, SymbolInfo]] # subset of modified where signature differs
    new_calls: set[str]                                     # symbol ids called by added+modified new symbols

def diff_symbols(old: list[SymbolInfo], new: list[SymbolInfo]) -> EditDiff
```

### `CodeRelay` contract (`git0/code/relay.py`) - the IDE layer codes against exactly this

```python
class ConflictInfo(BaseModel):
    kind: Literal["same_symbol", "dependency", "reverse_dependency", "intent"]
    severity: Literal["block", "warn"]          # intent = warn, others = block
    symbol: str                                  # the symbol the CHECKING agent touches/calls
    peer: str                                    # other agent id
    peer_change_id: str | None
    peer_summary: str                            # e.g. "A changed signature: apply_tax(amount) -> apply_tax(amount, region)"
    path: list[str]                              # symbol ids along the graph path (for highlighting)
    message: str                                 # one human sentence, no jargon

class CheckResult(BaseModel):
    conflicts: list[ConflictInfo]
    touched: list[str]                           # symbol ids this edit would add/modify/remove
    @property
    def blocking(self) -> bool                   # any severity == "block"

class ChangeRecord(BaseModel):
    change_ids: list[str]; touched: list[str]; summary: str

class PeerNotice(BaseModel):
    change_id: str; agent: str; symbol: str; kind: str; summary: str; ts: int

class CodeRelay:
    def __init__(self, graph: AsyncGraph): ...
    async def seed(self, files: dict[str, str], agents: dict[str, str]) -> dict   # agents: {"A": "Alice", "B": "Bob"}
    async def announce_intent(self, agent: str, task: str, symbols: list[str]) -> str   # deactivates agent's older intents
    async def check_edit(self, agent: str, path: str, old_source: str, new_source: str) -> CheckResult
    async def record_edit(self, agent: str, path: str, old_source: str, new_source: str, summary: str = "") -> ChangeRecord
    async def unseen_changes(self, agent: str) -> list[PeerNotice]   # other agents' changes this agent has not ACKED
    async def acknowledge(self, agent: str, change_ids: list[str]) -> int
    async def view(self) -> dict    # {"nodes":[{id,label,name,kind,props}], "links":[{source,target,type}]}
    async def symbol_ids(self) -> list[str]
```

`check_edit` logic (all graph-side, deterministic; the LLM never decides):
1. `diff_symbols(parse(old), parse(new))` -> touched = added + modified + removed ids; `calls` = new_calls.
2. **same_symbol**: un-ACKED Changes by other agents whose TOUCHED symbol is in touched. (Git would conflict
   or silently keep one side.)
3. **dependency**: un-ACKED Changes by other agents of kind `signature`/`removed` whose symbol is in `calls`
   (this edit calls a function the peer just changed the contract of). path = [my_symbol, peer_symbol].
4. **reverse_dependency**: for each of MY signature changes/removals: symbols that `CALLS*1..3` it and were
   touched by an un-ACKED peer Change (peer just wrote code relying on the old contract). path = the CALLS path.
5. **intent** (warn): other agents' active Intents that TARGET a touched symbol.
`record_edit` = parse, upsert File/Symbol (+ remove deleted symbols' DEFINES), rebuild CALLS for that file,
create one Change per touched symbol (kind `signature` when the signature changed), MADE/TOUCHED edges.
Ideally one query per write (pass lists, `CALL {}` subqueries); if two are unavoidable, comment why.
`ts` = ms epoch. Ids = `uuid4().hex[:12]`.

### MCP tools (add to `src/git0/mcp/server.py`; `tenant` = session id; graph = `ide_<tenant>`)

`code_announce_intent(tenant, agent, task, symbols)`, `code_check_edit(tenant, agent, path, old_source,
new_source)`, `code_record_edit(tenant, agent, path, old_source, new_source, summary)`,
`code_peer_activity(tenant, agent)` (= unseen_changes), `code_acknowledge(tenant, agent, change_ids)`,
`code_graph(tenant)`, `code_symbols(tenant)`. All return JSON-serialisable dicts/lists (`model_dump()`).
Helper `code_graph_for(tenant) -> AsyncGraph` validates tenant `^[a-z0-9_]{1,40}$` and selects `ide_<tenant>`;
put it in `git0/code/relay.py` so the IDE layer uses the same naming.

## IDE layer

### Session (`git0/ide/session.py`)

- `SessionManager` (singleton on app): `create() -> Session`, `get(sid)`, `end(sid)`, `sweep()`,
  `cleanup_orphans()` (startup), `run_sweeper()` task. Max `ide_max_sessions` (default 8) live sessions,
  else 503 "Demo is busy, try again in a minute".
- `Session`: `id` (12 hex), `root` = `<ide_workspace_root>/<sid>/`, `workspaces = {"A": root/"a", "B": root/"b"}`
  each a copy of `demo_project/` (`shutil.copytree`), `relay = CodeRelay(code_graph_for(sid))`,
  `agents = {"A": CodingAgent, "B": CodingAgent}`, `last_seen`, `turns_used` per agent.
- Event bus: `session.emit(type, **data)` appends `{type, ts, ...data}` to a ring buffer (last 500) and fans out
  to subscriber `asyncio.Queue`s. SSE subscribe replays the buffer first (so a reload restores state).
- Sweeper every 30 s: end sessions idle > `ide_session_ttl_s` (900) or with no SSE subscriber for
  > `ide_disconnect_grace_s` (120). End = cancel agent tasks, resolve pending questions as cancelled,
  `GRAPH.DELETE ide_<sid>` (ignore "empty key"), `shutil.rmtree(root)`.
- Limits: `ide_max_turns_per_agent` (8) user messages per agent per session; per run `UsageLimits(request_limit=20)`.

### Harness (`git0/ide/harness.py`) - "an open-source agent harness (pydantic-ai) + git0 hooks"

`CodingAgent(agent_id, label, workspace: Path, session, hooks: RelayHooks)`. One pydantic-ai `Agent` per
CodingAgent, `message_history` kept across turns. System prompt: you are a coding agent on <label>'s laptop
working in a clone of the team repo; make the smallest change; always read a file before editing; write whole
files with write_file; when a tool result says the write was blocked, follow the user's decision in it.

Tools (all paths repo-relative, forward slashes, sandboxed inside the workspace - reject `..`/absolute):
- `list_files()` - repo files.
- `read_file(path)` - content with line numbers.
- `write_file(path, content, summary)` - full new content + one-line summary of the change.
- `team_context()` - what teammates changed that you have not seen (via MCP `code_peer_activity`).

Every tool call runs through `_run_tool(name, args, fn)`:
1. emit `tool_call`
2. `decision = await hooks.pre_tool_use(name, args)` -> `HookDecision(action: allow|deny|context, message, conflicts)`
3. on **deny** (only for write_file with blocking conflicts): emit `conflict`, then **the harness itself** asks
   the human (does not rely on the cheap model to do it): `choice = await session.ask(agent, question, options)`
   (emit `ask_user`, await an `asyncio.Future` resolved by `POST .../answer`, timeout 300 s -> treat as "pause").
   Options:
   - `adopt` "Pull <peer>'s change and rework mine on top" -> copy peer's current version of every conflicting
     file into this workspace (simulated `git pull`), `code_acknowledge` those changes, emit `file_changed` for
     each, return to the model: "BLOCKED. User chose to adopt <peer>'s change. <peer>'s version of <files> is now
     in your workspace. Re-read them and redo your edit so it works with: <peer summaries>." (no write happens)
   - `override` "Keep my version anyway (I'll talk to <peer>)" -> acknowledge, perform the write, record it,
     return "Written (user override)".
   - `pause` "Stop - let <peer> finish first" -> return "BLOCKED. User paused you. Stop and summarise." and end.
4. on **context**: run the tool, append `\n\n[git0 relay] <message>` to the result (peer heads-up injection).
5. run the tool; emit `tool_result` (+ `file_changed` with full content for writes).
6. `await hooks.post_tool_use(name, args, result)` - for writes calls `code_record_edit`; emit `hook`, `graph_changed`.

`CodingAgent.send(text)` runs one turn as a background task: emits `agent_status` (thinking/tool/waiting_user/
idle/error), `agent_message` (user + assistant), `usage`. Before the first turn: `code_announce_intent(task=text,
symbols=[])` is fine (symbols can be filled by a cheap regex of `name(` matches against `code_symbols`).
If the model errors: fall back once to `ide_fallback_model`, else emit `error` loudly (no fake output).

### Hooks (`git0/ide/hooks.py`) - real MCP client over streamable HTTP

`RelayHooks(session_id, agent_id, workspace, mcp_url)`; uses the `mcp` client SDK (installed `mcp==2.3.0`; read
its source under `.venv/Lib/site-packages/mcp/client/` to get the exact streamable-HTTP client API) against
`ide_mcp_url` (default `http://127.0.0.1:{PORT}/mcp/`). Keep one client session per RelayHooks (lazy open,
reopen on failure). Every MCP call emits a `hook` event `{agent, phase, tool, mcp_tool, decision, detail, ms}`.
- `pre_tool_use("write_file")` -> `code_check_edit` with old = current workspace file (or "" if new);
  blocking -> deny; warn-only -> context; none -> allow.
- `pre_tool_use("read_file"|"list_files"|"team_context")` -> `code_peer_activity`; new (not yet surfaced to
  this agent in this session) notices -> context message "Heads-up: A changed shop/pricing.py::apply_tax
  (signature apply_tax(amount) -> apply_tax(amount, region)) 40 s ago." Also emit `peer_notice`.
- `post_tool_use("write_file")` -> `code_record_edit`; emit `graph_changed`.
If MCP is unreachable: fail loudly (emit `error`, deny the write) - never silently allow.

### API (`git0/ide/api.py`, prefix `/api/ide`)

| Method | Path | Body / result |
|---|---|---|
| POST | `/sessions` | -> `{session_id, agents:{A:{label,model},B:{...}}, files:[paths], presets:[...]}` |
| GET | `/sessions/{sid}/events` | SSE: replay buffer then live; `: ping` every 15 s; headers like app.py's SSE |
| GET | `/sessions/{sid}/files?agent=A` | `{path: content}` for that workspace |
| GET | `/sessions/{sid}/graph` | `CodeRelay.view()` |
| POST | `/sessions/{sid}/agents/{agent}/messages` | `{text}` -> 202 `{ok}`; 409 if agent busy; 429 if turns used up |
| POST | `/sessions/{sid}/questions/{qid}/answer` | `{choice}` -> `{ok}` |
| POST | `/sessions/{sid}/merge-check` | 3-way `git merge-file -p` of A vs B per file vs template -> `{files:[{path, conflicted, merged}]}` ("what plain git would say") |
| POST | `/sessions/{sid}/end` | also accepts sendBeacon (text/plain body) -> `{ok}` |
| GET | `/presets` | scenario presets |
Unknown session -> 404 `{"detail": "session expired"}`.

### SSE event contract (`event: <type>`, `data: {...}` always has `type`, `ts` (ms); `agent` when per-agent)

```
session        {session_id, agents, files}
agent_status   {agent, status: idle|thinking|tool|waiting_user|error}
agent_message  {agent, role: user|assistant, text}
tool_call      {agent, call_id, tool, args}            # args for write_file: {path, summary} (no content)
tool_result    {agent, call_id, tool, ok, summary}
hook           {agent, phase: PreToolUse|PostToolUse, tool, mcp_tool, decision: allow|deny|context|recorded, detail, ms}
file_changed   {agent, path, content}
graph_changed  {}
conflict       {agent, conflicts: ConflictInfo[]}
ask_user       {agent, question_id, question, options:[{id,label,description}]}
ask_resolved   {agent, question_id, choice}
peer_notice    {agent, from, message}
usage          {agent, input_tokens, output_tokens, requests}
error          {agent?, message}
session_ended  {reason}
```

## Web IDE (`web/ide/index.html` -> `web/src/ide/main.tsx`)

VS Code look (dark, `#1e1e1e` editor, `#252526` sidebar, `#333333` activity bar, `#007acc` status bar,
13px UI font, Consolas/`Cascadia Code` monospace). Libraries: existing React 19 + Tailwind 4; add
`@monaco-editor/react` for editors (read-only, diff highlight of lines changed since template) and reuse
`@falkordb/canvas` for the graph (see `web/src/components/MemoryCanvas.tsx` for how it is driven).
Layout:
- **Title bar**: "git0 relay - shop (2 clones)", session timer, "End session" button.
- **Activity bar** (icons) + **Explorer**: two roots "ALICE'S LAPTOP (Agent A)" / "BOB'S LAPTOP (Agent B)",
  file trees with colored dots on files the agent modified; click opens in that side's editor.
- **Editor area**: two editor groups side by side (A left, B right), tabs, Monaco; auto-opens the file an agent
  just wrote and highlights changed lines.
- **Right panel**: two agent chat panels (tabs or stacked): messages, compact tool-call chips, hook chips
  ("PreToolUse -> MCP code_check_edit -> DENY (2 conflicts)"), peer notices, **conflict card** with each
  conflict's message and an **ask_user card** with option buttons (calls answer API). Preset task buttons +
  "Run scenario (both at once)" + text input. Status pill per agent.
- **Bottom panel** tabs: "GIT0 RELAY" (chronological hook/MCP log, both agents, color-coded), "GRAPH"
  (FalkorDB code graph: File/Symbol/Change/Agent/Intent nodes, conflict `path` highlighted), "PROBLEMS"
  (conflict list), "MERGE CHECK" (button -> what plain git merge would say per file).
- **Status bar**: FalkorDB connected, session id, per-agent tokens, model name.
- On load: POST sessions -> open SSE. On `pagehide`: `navigator.sendBeacon(.../end)`. On `session_ended` or
  404: overlay "Session ended" with "Start a new session".
Must work in Chrome at 1366x768 and up; below 1024px show a simple stacked layout.
