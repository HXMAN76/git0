# Cypher queries Git0 depends on

Generated by `make cypher-docs` from [`cypher/`](../cypher). Do not edit by hand.

## `checkout`

Facts visible at the HEAD of $branch: added in an ancestor, not removed in an ancestor.
Uses the immutable Commit.ancestors list instead of a PARENT* walk (no path blow-up on merges).
FalkorDB has no EXISTS {} subqueries, hence OPTIONAL MATCH + none().

```cypher
MATCH (:Branch {name: $branch})-[:HEAD]->(h:Commit)
WITH h.ancestors + [h.id] AS anc
MATCH (f:Fact)-[:ADDED_IN]->(c:Commit)
WHERE c.id IN anc
OPTIONAL MATCH (f)-[:REMOVED_IN]->(r:Commit)
WITH f, anc, collect(r.id) AS rs
WHERE none(x IN rs WHERE x IN anc)
RETURN DISTINCT f.id AS id, f.s AS s, f.p AS p, f.o AS o, f.key AS key,
       f.confidence AS confidence, f.agent_id AS agent_id, f.created_at AS created_at
ORDER BY key
```

## `code_acknowledge`

The agent has seen (or, on "override", accepted) these Changes. An ACKED edge is what makes a Change stop
counting as a conflict for that agent. One write; the count of matched Changes comes back from the
subquery's RETURN so the caller knows how many ids were real.
Why a non-unit subquery here: the count has to come back, so this one does return rows.

```cypher
MERGE (me:Agent {id: $agent})
WITH me
CALL {
  WITH me
  UNWIND $ids AS cid
  MATCH (c:Change {id: cid})
  MERGE (me)-[:ACKED]->(c)
  RETURN count(c) AS n
}
RETURN n
```

## `code_announce_intent`

An agent says "I am about to work on these symbols". Deactivates the agent's older intents so only its
latest task reads as active. One query: the deactivation, the new Intent and its TARGETS edges together.
Intents are warnings only (see code_conflicts_intent): announcing is cheap and can go stale.

```cypher
MERGE (me:Agent {id: $agent})
WITH me
CALL {
  WITH me
  MATCH (me)-[:INTENDS]->(old:Intent)
  WHERE old.active = true
  SET old.active = false
}
WITH me
CREATE (i:Intent {id: $id, agent: $agent, task: $task, ts: $ts, active: true})
CREATE (me)-[:INTENDS]->(i)
WITH i
CALL {
  WITH i
  UNWIND $symbols AS sid
  MATCH (s:Symbol {id: sid})
  MERGE (i)-[:TARGETS]->(s)
}
RETURN i.id AS id
```

## `code_conflicts_dependency`

dependency (block): the checking edit calls a function that another agent just changed the contract of
(signature or removed) and that the checking agent has not ACKED. $edges are [{src, dst}] taken from the
new code of the added and modified symbols, so src is the checking agent's own symbol.
Why UNWIND first: each edge is matched on its own; an empty $edges correctly yields no conflicts.

```cypher
UNWIND $edges AS e
MATCH (s:Symbol)
WHERE s.id = e.dst
MATCH (ag:Agent)-[:MADE]->(peer:Change)-[:TOUCHED]->(s)
WHERE peer.kind IN ['signature', 'removed'] AND ag.id <> $agent
WITH e, ag, peer, s, [(me:Agent)-[:ACKED]->(peer) | me.id] AS ackers
WHERE NOT $agent IN ackers
RETURN e.src AS src, s.id AS dst, ag.id AS peer, ag.label AS peer_label, peer.id AS change_id,
       peer.summary AS summary
```

## `code_conflicts_intent`

intent (warn only): another agent has an active announced intent that targets a symbol this edit touches.
Why warn and not block: an intent is a plan, not a change, and plans go stale. The human decides.

```cypher
MATCH (ag:Agent)-[:INTENDS]->(i:Intent)-[:TARGETS]->(s:Symbol)
WHERE i.active = true AND ag.id <> $agent AND s.id IN $touched
RETURN s.id AS symbol, ag.id AS peer, ag.label AS peer_label, i.id AS intent_id, i.task AS task
```

## `code_conflicts_reverse`

reverse_dependency (block): the checking edit changes the contract (signature) or removes a function that
code another agent just wrote relies on. Walks CALLS up to 3 hops from each changed symbol back to callers
that a peer touched and the checking agent has not ACKED. path = caller ... changed symbol, for the graph.
Why the peer's Change must touch the caller: that is the code that was written against the old contract.

```cypher
UNWIND $contract AS cid
MATCH (target:Symbol)
WHERE target.id = cid
MATCH p = (caller:Symbol)-[:CALLS*1..3]->(target)
MATCH (ag:Agent)-[:MADE]->(peer:Change)-[:TOUCHED]->(caller)
WHERE ag.id <> $agent
WITH target, caller, ag, peer, [n IN nodes(p) | n.id] AS path,
     [(me:Agent)-[:ACKED]->(peer) | me.id] AS ackers
WHERE NOT $agent IN ackers
RETURN target.id AS symbol, caller.id AS caller, ag.id AS peer, ag.label AS peer_label,
       peer.id AS change_id, peer.summary AS summary, path
```

## `code_conflicts_same_symbol`

same_symbol (block): another agent's Change touched a symbol this edit also touches, and the checking agent
has not ACKED that Change yet. Git would conflict here or silently keep one side. Read-only.
Why the ACKED test is a pattern comprehension and not EXISTS {}: FalkorDB has no EXISTS, and a list of
acking agent ids plus NOT IN is the same check.

```cypher
MATCH (ag:Agent)-[:MADE]->(peer:Change)-[:TOUCHED]->(s:Symbol)
WHERE s.id IN $touched AND ag.id <> $agent
WITH ag, peer, s, [(me:Agent)-[:ACKED]->(peer) | me.id] AS ackers
WHERE NOT $agent IN ackers
RETURN ag.id AS peer, ag.label AS peer_label, peer.id AS change_id, peer.summary AS summary,
       peer.kind AS change_kind, s.id AS symbol
```

## `code_record_conflicts`

Writes the conflicts a blocked edit raised as Conflict nodes, in one query, so the graph shows the story:
(Agent)-[:RAISED]->(Conflict)-[:ON]->(Symbol the checking agent touched) and, when a peer Change is involved,
(Conflict)-[:AGAINST]->(Change). Every Conflict starts with resolution 'pending'; code_resolve_conflicts sets it.
Why unit CALL blocks: each step needs the UNWIND rows and must not stop the others. An intent conflict has no
peer Change, so its change_id is '' and the AGAINST step simply matches nothing for it.
Why the ids come from the caller: the harness puts them in the `conflict` SSE event, so the UI can link the card.
Why the final MATCH: it confirms each Conflict exists before the caller treats the ids as recorded.

```cypher
MERGE (me:Agent {id: $agent})
WITH me
CALL {
  WITH me
  UNWIND $conflicts AS c
  CREATE (x:Conflict {id: c.id, agent: $agent, peer: c.peer, kind: c.kind, message: c.message, ts: c.ts,
                      resolution: 'pending'})
  CREATE (me)-[:RAISED]->(x)
}
CALL {
  WITH me
  UNWIND $conflicts AS c
  MATCH (x:Conflict {id: c.id})
  MATCH (s:Symbol {id: c.symbol})
  MERGE (x)-[:ON]->(s)
}
CALL {
  WITH me
  UNWIND $conflicts AS c
  MATCH (x:Conflict {id: c.id})
  MATCH (ch:Change)
  WHERE ch.id = c.change_id
  MERGE (x)-[:AGAINST]->(ch)
}
WITH me
UNWIND $conflicts AS c
MATCH (x:Conflict {id: c.id})
RETURN x.id AS id
```

## `code_record_edit`

Records one file write in one query: upserts the file's symbols, marks symbols that vanished as removed,
rebuilds the CALLS edges out of this file's symbols, and adds one Change per touched symbol.
Why one query: a write must land all-or-nothing (FalkorDB has no transactions).
Why CALLS are deleted before they are recreated: a call the author removed must not keep an edge alive.
Why removed symbols stay as nodes (removed = true): a Change needs a TOUCHED target that later checks find.
Why the sweep: a symbol the graph still DEFINES but the new source no longer has (graph drift) is retired too.

```cypher
MERGE (f:File {path: $path})
WITH f
MERGE (me:Agent {id: $agent})
WITH f, me
CALL {
  WITH f
  UNWIND $syms AS s
  MERGE (n:Symbol {id: s.id})
  SET n.name = s.name, n.path = s.path, n.kind = s.kind, n.signature = s.signature,
      n.body_hash = s.body_hash, n.line = s.line, n.end_line = s.end_line, n.removed = false
  MERGE (f)-[:DEFINES]->(n)
}
CALL {
  WITH f
  UNWIND $gone AS g
  MERGE (n:Symbol {id: g.id})
  SET n.name = g.name, n.path = g.path, n.kind = g.kind, n.removed = true
  WITH f, n
  MATCH (f)-[d:DEFINES]->(n)
  DELETE d
}
CALL {
  WITH f
  MATCH (f)-[d:DEFINES]->(n:Symbol)
  WHERE NOT n.id IN $ids
  SET n.removed = true
  DELETE d
}
CALL {
  WITH f
  MATCH (f)-[:DEFINES]->(n:Symbol)-[c:CALLS]->()
  DELETE c
}
CALL {
  WITH f
  UNWIND $gone AS g
  MATCH (n:Symbol {id: g.id})-[c:CALLS]->()
  DELETE c
}
CALL {
  WITH f
  UNWIND $calls AS c
  MATCH (a:Symbol {id: c.src}), (b:Symbol {id: c.dst})
  MERGE (a)-[:CALLS]->(b)
}
CALL {
  WITH f, me
  UNWIND $changes AS ch
  CREATE (c:Change {id: ch.id, agent: $agent, ts: $ts, path: $path, symbol: ch.symbol, kind: ch.kind,
                    summary: ch.summary, old_signature: ch.old_signature, new_signature: ch.new_signature})
  CREATE (me)-[:MADE]->(c)
  WITH c, ch
  MATCH (s:Symbol {id: ch.symbol})
  CREATE (c)-[:TOUCHED]->(s)
}
RETURN f.path AS path
```

## `code_resolve_conflicts`

The human's choice on a blocked write: sets resolution on each Conflict (pending -> adopt | override | pause).
Why MATCH and not MERGE: a Conflict is created when the write is blocked, so an unknown id must not invent one.
Why count(x): the caller gets back how many Conflicts matched, so a stale id is visible instead of silent.

```cypher
UNWIND $ids AS cid
MATCH (x:Conflict {id: cid})
SET x.resolution = $resolution
RETURN count(x) AS n
```

## `code_seed`

Seeds one IDE session's code graph in a single write: File and Symbol nodes, DEFINES, CALLS and Agents.
Why one query: FalkorDB has no multi-query transactions, so a half-seeded graph must not be possible.
Re-running is safe: every node and edge is MERGEd by its domain id.
Why UNWIND [1] first: CALL {} subqueries need an outer row to start from. Each CALL is a unit subquery
(no RETURN), so it runs once per outer row and an empty input list only skips its own work.

```cypher
UNWIND [1] AS _once
CALL {
  WITH _once
  UNWIND $files AS fp
  MERGE (:File {path: fp})
}
CALL {
  WITH _once
  UNWIND $symbols AS s
  MATCH (f:File {path: s.path})
  MERGE (n:Symbol {id: s.id})
  SET n.name = s.name, n.path = s.path, n.kind = s.kind, n.signature = s.signature,
      n.body_hash = s.body_hash, n.line = s.line, n.end_line = s.end_line, n.removed = false
  MERGE (f)-[:DEFINES]->(n)
}
CALL {
  WITH _once
  UNWIND $calls AS c
  MATCH (a:Symbol {id: c.src}), (b:Symbol {id: c.dst})
  MERGE (a)-[:CALLS]->(b)
}
CALL {
  WITH _once
  UNWIND $agents AS ag
  MERGE (a:Agent {id: ag.id})
  SET a.label = ag.label
}
RETURN _once AS ok
```

## `code_symbol_ids`

Live symbol ids (not removed) for the IDE's symbol picker and for auto-filling an intent's targets.
Why coalesce on removed: a symbol written by an older seed may have no removed flag at all; that means live.

```cypher
MATCH (s:Symbol)
WHERE coalesce(s.removed, false) = false
RETURN s.id AS id
ORDER BY id
```

## `code_view_links`

Every edge the IDE's graph panel draws: DEFINES, CALLS, MADE, TOUCHED, INTENDS, TARGETS, ACKED, and the
conflict story RAISED (agent -> Conflict), ON (Conflict -> Symbol), AGAINST (Conflict -> peer Change).
Endpoints are returned as the same ids code_view_nodes uses (coalesce(id, path)), so the UI can join them.

```cypher
MATCH (a)-[r]->(b)
WHERE type(r) IN ['DEFINES', 'CALLS', 'MADE', 'TOUCHED', 'INTENDS', 'TARGETS', 'ACKED',
                  'RAISED', 'ON', 'AGAINST']
RETURN coalesce(a.id, a.path) AS source, coalesce(b.id, b.path) AS target, type(r) AS type
```

## `code_view_nodes`

Every File, Symbol, Change, Agent, Intent and Conflict node for the IDE's graph panel, one row each.
Why coalesce(id, path): File nodes are keyed by path; every other label has an id. The UI wants one id field.
Only the properties the panel shows are returned, so the response stays small. ts is returned for Change,
Intent and Conflict so the panel can draw a timeline.

```cypher
MATCH (n)
WHERE n:File OR n:Symbol OR n:Change OR n:Agent OR n:Intent OR n:Conflict
RETURN labels(n)[0] AS label, coalesce(n.id, n.path) AS id, n.name AS name, n.path AS path,
       n.kind AS kind, n.signature AS signature, n.summary AS summary, n.task AS task,
       n.label AS agent_label, n.agent AS agent, n.active AS active, n.removed AS removed,
       n.ts AS ts, n.peer AS peer, n.message AS message, n.resolution AS resolution
```

## `commit_cas`

Atomic compare-and-set commit (M15: one query = one transaction).
Moves HEAD only if it still points at $expected; 0 rows back = HEAD moved, caller rebases + retries.
Writes the commit, author, session + episodes, facts, procedures, removals and DERIVED_FROM edges together.
One visible value per key: before adding a fact, any fact with the same key `s|p` that is visible at the
parent is REMOVED_IN this commit, so a branch view never holds two values for one key. Edges are MERGEd,
so an explicit `removed` entry for the same fact does not create a duplicate. The request model rejects
two new facts with the same key in one commit.
NOTE: use CALL {} unit subqueries, never a bare UNWIND: UNWIND [] drops the row and a successful
commit would look like a CAS failure (verified on FalkorDB, see docs/research/01-falkordb.md).

```cypher
MATCH (b:Branch {name: $branch})-[r:HEAD]->(h:Commit {id: $expected})
CREATE (n:Commit {id: $id, seq: h.seq + 1, msg: $msg, ts: timestamp(), agent_id: $agent_id,
                  kind: $kind, ancestors: h.ancestors + [h.id]})-[:PARENT]->(h)
DELETE r
CREATE (b)-[:HEAD]->(n)
MERGE (a:Agent {id: $agent_id})
CREATE (a)-[:AUTHORED]->(n)
WITH n
CALL {
  WITH n
  UNWIND $episodes AS e
  MERGE (s:Session {id: e.session_id})
  ON CREATE SET s.started_at = timestamp()
  CREATE (ep:Episode {id: e.id, text: e.text, session_id: e.session_id, ts: timestamp()})
  CREATE (s)-[:HAS_TURN]->(ep)
  CREATE (n)-[:FROM_EPISODE]->(ep)
}
CALL {
  WITH n
  UNWIND $facts AS f
  MATCH (old:Fact {key: f.s + '|' + f.p})-[:ADDED_IN]->(c:Commit)
  WHERE c.id IN n.ancestors
  OPTIONAL MATCH (old)-[:REMOVED_IN]->(r:Commit)
  WITH n, old, collect(r.id) AS rs
  WHERE none(x IN rs WHERE x IN n.ancestors)
  MERGE (old)-[:REMOVED_IN]->(n)
}
CALL {
  WITH n
  UNWIND $facts AS f
  CREATE (:Fact {id: f.id, s: f.s, p: f.p, o: f.o, key: f.s + '|' + f.p, confidence: f.confidence,
                 agent_id: n.agent_id, created_at: timestamp()})-[:ADDED_IN]->(n)
}
CALL {
  WITH n
  UNWIND $procedures AS pr
  CREATE (:Procedure {id: pr.id, trigger: pr.trigger, steps: pr.steps, confidence: pr.confidence,
                      agent_id: n.agent_id, created_at: timestamp()})-[:ADDED_IN]->(n)
}
CALL {
  WITH n
  UNWIND $removed_procedures AS pid
  MATCH (x:Procedure {id: pid})
  CREATE (x)-[:REMOVED_IN]->(n)
}
CALL {
  WITH n
  UNWIND $removed AS rid
  MATCH (x:Fact {id: rid})
  MERGE (x)-[:REMOVED_IN]->(n)
}
CALL {
  WITH n
  UNWIND $derived AS d
  MATCH (child:Fact {id: d.child}), (parent:Fact {id: d.parent})
  CREATE (child)-[:DERIVED_FROM]->(parent)
}
RETURN n.id AS id, n.seq AS seq
```

## `commit_changes`

What one commit changed: facts ADDED_IN and facts REMOVED_IN commit $commit, tagged by change type.
revert needs both halves: the added facts get removed, the removed ones (e.g. the old value a new fact
replaced) get restored. Not visibility-filtered: the caller intersects with the branch checkout.

```cypher
MATCH (f:Fact)-[:ADDED_IN]->(:Commit {id: $commit})
RETURN 'added' AS change, f.id AS id, f.s AS s, f.p AS p, f.o AS o, f.key AS key, f.confidence AS confidence
UNION ALL
MATCH (f:Fact)-[:REMOVED_IN]->(:Commit {id: $commit})
RETURN 'removed' AS change, f.id AS id, f.s AS s, f.p AS p, f.o AS o, f.key AS key, f.confidence AS confidence
```

## `create_branch`

Fork a new branch at the current HEAD of $from. Returns 0 rows if $from is missing or $name exists.

```cypher
MATCH (:Branch {name: $from})-[:HEAD]->(h:Commit)
OPTIONAL MATCH (dup:Branch {name: $name})

```

```cypher
MATCH (d:Fact)-[:DERIVED_FROM*1..6]->(:Fact {id: $fid})
```

## `dependents_visible`

Dependents of fact $fid (DERIVED_FROM up to 6 hops) that are still visible at commit $head.
plan_merge needs this per side: a conflict card shows what each choice would orphan, and latest-wins
removes the loser's visible dependents. Same visibility rule as checkout (ancestors list + none()).

```cypher
MATCH (d:Fact)-[:DERIVED_FROM*1..6]->(:Fact {id: $fid})
MATCH (h:Commit {id: $head})
WITH d, h.ancestors + [h.id] AS anc
MATCH (d)-[:ADDED_IN]->(c:Commit)
WHERE c.id IN anc
OPTIONAL MATCH (d)-[:REMOVED_IN]->(r:Commit)
WITH d, anc, collect(r.id) AS rs
WHERE none(x IN rs WHERE x IN anc)
RETURN DISTINCT d.id AS id, d.s AS s, d.p AS p, d.o AS o, d.key AS key,
       d.confidence AS confidence, d.agent_id AS agent_id, d.created_at AS created_at
ORDER BY key
```

## `fact_links`

Direct DERIVED_FROM neighbours of fact $fid: `children` derive from it, `parents` it derives from.
Restoring a fact (merge "keep the base value", revert) creates a fresh copy under a new id; the copy must
inherit these edges or later merges cannot see what depends on it (and would skip the dependency conflict).
Read-only. OPTIONAL MATCH + collect keeps the row (with empty lists) when the fact has no links.

```cypher
MATCH (x:Fact {id: $fid})
OPTIONAL MATCH (c:Fact)-[:DERIVED_FROM]->(x)
WITH x, collect(DISTINCT c.id) AS children
OPTIONAL MATCH (x)-[:DERIVED_FROM]->(p:Fact)
RETURN children, collect(DISTINCT p.id) AS parents
```

## `fact_lookup`

"Is X in team memory?" (M10). 0 rows = no path from the branch HEAD = "not in memory", never a guess.

```cypher
MATCH (:Branch {name: $branch})-[:HEAD]->(h:Commit)
WITH h.ancestors + [h.id] AS anc
MATCH (f:Fact {key: $key})-[:ADDED_IN]->(c:Commit)
WHERE c.id IN anc
OPTIONAL MATCH (f)-[:REMOVED_IN]->(r:Commit)
WITH f, anc, collect(r.id) AS rs
WHERE none(x IN rs WHERE x IN anc)
RETURN f.id AS id, f.o AS o
```

```cypher
MATCH (f:Fact)

```

## `graph_view`

The memory graph behind a branch, for the UI's live graph view (judges see what the agents remember).
One row per Fact visible at the HEAD of $branch (same visibility rule as `checkout`), newest first and capped
at $limit so the canvas stays fast. Each row carries the commit that added the fact, the agents that
AUTHORED that commit, the commit's episodes as [id, text] pairs, and the ids of the facts it is
DERIVED_FROM. Parents can be hidden or past the cap; the caller keeps only edges between returned facts.
Pattern comprehensions (one level, never nested) keep it one row per fact without collect() bookkeeping.

```cypher
MATCH (:Branch {name: $branch})-[:HEAD]->(h:Commit)
WITH h.ancestors + [h.id] AS anc
MATCH (f:Fact)-[:ADDED_IN]->(c:Commit)
WHERE c.id IN anc
OPTIONAL MATCH (f)-[:REMOVED_IN]->(r:Commit)
WITH f, c, anc, collect(r.id) AS rs
WHERE none(x IN rs WHERE x IN anc)
WITH f, c
ORDER BY f.created_at DESC, f.id
LIMIT $limit
RETURN f.id AS id, f.s AS s, f.p AS p, f.o AS o, f.key AS key, f.confidence AS confidence,
       f.agent_id AS agent_id,
       c.id AS commit_id, c.msg AS commit_msg, c.kind AS commit_kind, c.seq AS commit_seq,
       [(a:Agent)-[:AUTHORED]->(c) | a.id] AS authors,
       [(c)-[:FROM_EPISODE]->(e:Episode) | [e.id, e.text]] AS episodes,
       [(f)-[:DERIVED_FROM]->(parent:Fact) | parent.id] AS parents
```

## `init_repo`

Create the root commit and the `main` branch for a fresh tenant graph. Idempotent.

```cypher
MERGE (b:Branch {name: 'main'})
WITH b
OPTIONAL MATCH (b)-[:HEAD]->(existing:Commit)
WITH b, existing
WHERE existing IS NULL
CREATE (root:Commit {id: $root_id, seq: 0, msg: 'init', ts: timestamp(), agent_id: 'system', ancestors: []})
CREATE (b)-[:HEAD]->(root)
RETURN root.id AS id
```

## `log`

Commit history of $branch, newest first, with author and fact counts.
parents: ids of the commit's PARENT edges (two for a merge, none for the root) so the UI can draw the real
DAG instead of guessing edges from log order. Unordered: FalkorDB's collect gives no edge order.

```cypher
MATCH (:Branch {name: $branch})-[:HEAD]->(h:Commit)
WITH h.ancestors + [h.id] AS anc
MATCH (c:Commit)
WHERE c.id IN anc
OPTIONAL MATCH (c)-[:PARENT]->(p:Commit)
WITH c, collect(p.id) AS parents
OPTIONAL MATCH (added:Fact)-[:ADDED_IN]->(c)
WITH c, parents, count(added) AS added
OPTIONAL MATCH (removed:Fact)-[:REMOVED_IN]->(c)
RETURN c.id AS id, c.seq AS seq, c.msg AS msg, c.agent_id AS agent_id, c.ts AS ts, c.kind AS kind,
       added, count(removed) AS removed, parents
ORDER BY c.seq DESC, c.ts DESC
LIMIT $limit
```

## `merge_base`

Latest common ancestor of two branch HEADs: intersect ancestor lists, highest seq wins.
seq is strictly increasing along PARENT edges (merge commits use max(parent seqs) + 1).

```cypher
MATCH (:Branch {name: $a})-[:HEAD]->(ha:Commit), (:Branch {name: $b})-[:HEAD]->(hb:Commit)
WITH ha.ancestors + [ha.id] AS aa, hb.ancestors + [hb.id] AS bb
MATCH (c:Commit)
WHERE c.id IN aa AND c.id IN bb
RETURN c.id AS id, c.seq AS seq
ORDER BY c.seq DESC
LIMIT 1
```

## `merge_commit`

Atomic merge commit (one query = one transaction). CAS on the target HEAD: 0 rows back = target HEAD
moved, caller re-diffs and retries. The merge commit has TWO parents (target head, source head) and its
ancestors are the deduped union of both histories, so checkout (which reads Commit.ancestors) sees the
union of both branches' facts with no extra work.
$removed: fact ids the merge decided to hide (REMOVED_IN the merge commit). MERGE, not CREATE, so a fact
already removed by this commit is not linked twice.
$resolutions: one map per resolved conflict {key, p, side, base_id, ours_id, theirs_id}; ids may be null
(a side that did not exist). Each becomes a Conflict node linked to its facts, plus a Precedent counter
keyed by (predicate, chosen side) that the "learns from your resolutions" feature reads.
$facts: NewFact maps to create in this commit. Only used to RESTORE a dependency-conflict winner: the other
side's commits removed the base-valued fact, so the union hides it and choosing it needs a fresh copy.
Same shape as the facts block in commit_cas, without retiring old values (the loser is in $removed).
$derived: {child, parent} pairs, same shape as commit_cas. Used with $facts so a restored copy inherits the
original's lineage in both directions (its dependents now also derive from the copy, and the copy derives
from the original's parents). Runs after the facts block so the copy exists when the edges are matched.
NOTE: CALL {} unit subqueries, never a bare UNWIND: UNWIND [] drops the row and fakes a CAS failure.

```cypher
MATCH (b:Branch {name: $target})-[r:HEAD]->(ht:Commit {id: $expected_target})
MATCH (hs:Commit {id: $source_head})
CREATE (n:Commit {id: $id, kind: 'merge', msg: $msg, ts: timestamp(), agent_id: $agent_id,
                  seq: CASE WHEN ht.seq > hs.seq THEN ht.seq ELSE hs.seq END + 1,
                  ancestors: list.dedup(ht.ancestors + hs.ancestors + [ht.id, hs.id])})
CREATE (n)-[:PARENT]->(ht)
CREATE (n)-[:PARENT]->(hs)
DELETE r
CREATE (b)-[:HEAD]->(n)
MERGE (a:Agent {id: $agent_id})
CREATE (a)-[:AUTHORED]->(n)
WITH n
CALL {
  WITH n
  UNWIND $removed AS rid
  MATCH (x:Fact {id: rid})
  MERGE (x)-[:REMOVED_IN]->(n)
}
CALL {
  WITH n
  UNWIND $facts AS f
  CREATE (:Fact {id: f.id, s: f.s, p: f.p, o: f.o, key: f.s + '|' + f.p, confidence: f.confidence,
                 agent_id: n.agent_id, created_at: timestamp()})-[:ADDED_IN]->(n)
}
CALL {
  WITH n
  UNWIND $derived AS d
  MATCH (child:Fact {id: d.child}), (parent:Fact {id: d.parent})
  CREATE (child)-[:DERIVED_FROM]->(parent)
}
CALL {
  WITH n
  UNWIND $resolutions AS r
  CREATE (cf:Conflict {key: r.key, status: 'resolved', side: r.side, ts: timestamp()})-[:RESOLVED_IN]->(n)
  WITH cf, r
  OPTIONAL MATCH (ours:Fact {id: r.ours_id})
  OPTIONAL MATCH (theirs:Fact {id: r.theirs_id})
  OPTIONAL MATCH (base:Fact {id: r.base_id})
  FOREACH (_ IN CASE WHEN ours IS NULL THEN [] ELSE [1] END | CREATE (cf)-[:SIDE_A]->(ours))
  FOREACH (_ IN CASE WHEN theirs IS NULL THEN [] ELSE [1] END | CREATE (cf)-[:SIDE_B]->(theirs))
  FOREACH (_ IN CASE WHEN base IS NULL THEN [] ELSE [1] END | CREATE (cf)-[:BASE]->(base))
  MERGE (pr:Precedent {key_pattern: r.p, choice: r.side})
  ON CREATE SET pr.count = 1
  ON MATCH SET pr.count = pr.count + 1
  CREATE (cf)-[:RESOLVED_BY]->(pr)
}
RETURN n.id AS id, n.seq AS seq
```

## `precedent_lookup`

Most-chosen past resolution for predicate $p (a (:Precedent) is saved on every human resolution).
plan_merge shows it on the conflict card as a suggestion; it never decides anything.

```cypher
MATCH (pr:Precedent {key_pattern: $p})
RETURN pr.choice AS choice, pr.count AS count
ORDER BY pr.count DESC
LIMIT 1
```

## `room_last_seen`

When was this room last used? Read by the room sweep (#30) for every `team_*` graph.
Rooms created before the Room node existed have none, so fall back to the earliest commit's ts (the root
commit from `init`). Both `CALL {}`s aggregate, so an empty graph still returns one row: `last_seen` = null,
which the sweep treats as "oldest possible".

```cypher
CALL { OPTIONAL MATCH (r:Room) RETURN max(r.last_seen) AS room_seen }
CALL { OPTIONAL MATCH (c:Commit) RETURN min(c.ts) AS root_ts }
RETURN coalesce(room_seen, root_ts) AS last_seen
```

```cypher
MATCH (r:Rule)
RETURN r.p AS p, r.strategy AS strategy
```

## `scorecard`

Live counts for the demo scorecard, in ONE read query so the whole thing is a single measurable round trip.
Each `CALL {}` ends in an aggregation, which always yields one row, so an empty graph returns zeros
instead of zero rows (chained MATCH ... WITH would drop the row). `commits` counts every commit that has a
`kind` (commit, merge, revert, handoff, seed) and so excludes the kind-less root created by `init`.
`facts_on_main` / `procedures_on_main` use the standard visibility rule (see `checkout`).
`precedents_reused` = how many resolutions were answered by an existing precedent (count - 1 per node).

```cypher
CALL { MATCH (e:Episode) RETURN count(e) AS episodes }
CALL { MATCH (s:Session) RETURN count(s) AS sessions }
CALL {
  MATCH (:Branch {name: 'main'})-[:HEAD]->(h:Commit)
  WITH h.ancestors + [h.id] AS anc
  MATCH (f:Fact)-[:ADDED_IN]->(c:Commit)
  WHERE c.id IN anc
  OPTIONAL MATCH (f)-[:REMOVED_IN]->(r:Commit)
  WITH f, anc, collect(r.id) AS rs
  WHERE none(x IN rs WHERE x IN anc)
  RETURN count(DISTINCT f) AS facts_on_main
}
CALL {
  MATCH (:Branch {name: 'main'})-[:HEAD]->(h:Commit)
  WITH h.ancestors + [h.id] AS anc
  MATCH (pr:Procedure)-[:ADDED_IN]->(c:Commit)
  WHERE c.id IN anc
  OPTIONAL MATCH (pr)-[:REMOVED_IN]->(r:Commit)
  WITH pr, anc, collect(r.id) AS rs
  WHERE none(x IN rs WHERE x IN anc)
  RETURN count(DISTINCT pr) AS procedures_on_main
}
CALL {
  MATCH (c:Commit)
  WHERE c.kind IS NOT NULL
  RETURN count(c) AS commits,
         sum(CASE WHEN c.kind = 'merge' THEN 1 ELSE 0 END) AS merges,
         sum(CASE WHEN c.kind = 'revert' THEN 1 ELSE 0 END) AS reverts,
         sum(CASE WHEN c.kind = 'handoff' THEN 1 ELSE 0 END) AS handoffs
}
CALL { MATCH (cf:Conflict {status: 'resolved'}) RETURN count(cf) AS conflicts_resolved }
CALL {
  MATCH (p:Precedent)
  WHERE p.count > 1
  RETURN coalesce(sum(p.count - 1), 0) AS precedents_reused
}
CALL { MATCH (a:Agent) RETURN count(a) AS agents }
RETURN episodes, sessions, facts_on_main, procedures_on_main, commits, merges, reverts, handoffs,
       conflicts_resolved, precedents_reused, agents
```

## `seed_rules`

Seed the per-predicate merge rules (Rule nodes) for a tenant graph. Idempotent: ON CREATE only, so a
human-edited strategy survives a re-init. Rules live in the graph so the merge decision stays a query
over data, not hard-coded Python.

```cypher
UNWIND $rules AS r
MERGE (x:Rule {p: r.p})
ON CREATE SET x.strategy = r.strategy
RETURN count(x) AS rules
```

## `touch_room`

Stamp visitor activity on this tenant's single `(:Room)` node (#30). Runs after every seed (= every page load)
and every POST route, so the background sweep can delete rooms idle longer than TENANT_TTL_SECONDS and evict
the least recently seen ones when there are more than MAX_ROOMS. MERGE keeps it to one Room per graph.
Read the clock once: two timestamp() calls can straddle a millisecond and give a new room created_at != last_seen.

```cypher
WITH timestamp() AS now
MERGE (r:Room)
ON CREATE SET r.created_at = now
SET r.last_seen = now
RETURN r.last_seen AS last_seen
```
